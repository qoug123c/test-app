## config.php 
### ini_set();
[php.net](https://www.php.net/manual/ja/function.ini-set.php)

 PHPの **「設定オプション」の値を一時的に書きかえるための関数** です。

 PHPには、あらかじめ php.ini というファイルで決められた「基本ルール（設定）」があります。しかし、特定のプログラムを動かすときだけ、そのルールを変えたい場合があります。

 スクリプトの冒頭で `ini_set()` を使うことで、そのプログラムが実行されている間だけルールを上書きできます。

- **【シチュエーション】**
  - 「このプログラムの間だけ、エラーを画面に表示させたい」
  - 「この処理だけ、特別にメモリをたくさん使わせてほしい」

---
### error_reporting();
[php.net](https://www.php.net/manual/ja/function.error-reporting.php)

PHPが **「どんな種類の間違い（エラー）を報告するか」を設定するための関数**です。

PHPには色々なレベルの「間違い」があります。
- すべてのミスを報告 (**E_ALL**): 

  E_ALL をセットするのは、主に **プログラムを作っている最中（開発中）** です。小さなミスが後で大きなバグ（不具合）になるのを防ぐために、E_ALL にして全ての指摘をしてもらうのが一番です。

- 致命的なエラー (**E_ERROR**): 

  プログラムが止まってしまうほどの大失敗です（たとえば、前回お話しした require でファイルが見つからない時などに発生します）。

- 警告 (**E_WARNING**): 


`error_reporting()` を使うと、「致命的なエラー（大失敗）だけ教えて！」とか「細かい注意（小さなミス）も全部教えて！」という風に、報告してほしいエラーの種類を自由に選ぶことができます。

---
### set_error_handler();
[php.net](https://www.php.net/manual/ja/function.set-error-handler.php)

PHPでエラーが起きたときに　**「あらかじめ決まった動きではなく、自分で作ったオリジナルの動き（関数）をさせる」**　ための関数です。

通常、PHPでエラーが起きると、画面に「エラーですよ！」と文字が出るだけですが、この関数を使うと **「エラーが起きたら、こっそりノートにメモして、画面には可愛いイラストを出してね」** といった自分専用のルールを作ることができます

- **【できること】**
  - エラーを隠す: 恥ずかしいのでエラーを画面には出さない。
  - ログに記録する: どんなエラーが起きたか、後で確認するためにファイルに保存する。
  - 特別なお知らせ: 大事なプログラムなら、エラーが起きた瞬間にメールを送る。 etc...

### function errorHandler($errNo, $errStr, $errFile, $errLine)
自作メソッド。

- **【引数】**
  - **$errNo**：エラーの番号（種類）。
  - **$errStr**：エラーのメッセージ（内容）。
  - **$errFile**：エラーが起きたファイルの名前。
  - **$errLine**：エラーが起きた行番号。

- **【していること】**
  1. エラーの種類を厳しくチェック (===):
    ```
    if ($errNo === E_NOTICE || $errNo === E_WARNING)
    ```
     ここでは「ちょっとしたヒント (E_NOTICE)」か「警告 (E_WARNING)」のときだけ動くように設定しています。
  
  2. 名前を決める (三項演算子 ? :):
   ```
   $errTitle = $errNo === E_NOTICE ? 'Notice' : 
   ```
   `'Warning';` 番号を見て、画面に出すタイトルを「Notice」にするか「Warning」にするか決めています。

  3. きれいに整える (htmlspecialchars): 
    - エラーの内容やファイル名に、変な記号が入って画面が崩れないように安全に加工しています。
    - [`htmlspecialchars()`](https://www.php.net/manual/ja/function.htmlspecialchars.php)：PHPにおいて **「特殊文字を HTML エンティティに変換する」** ための関数です。
      - 具体的には、HTMLの中で特別な意味を持つ記号（例えば < や & など）を、ブラウザがタグとしてではなく、単なる「文字」として正しく表示できるように `&lt;` や `&amp;` といった形式（HTMLエンティティ）に置き換える役割を担います。

  4. 画面に表示して、即終了！ (echo と exit):
    ```
    echo '<b>' . $errTitle ... 
    ```
    エラー情報を太字で見やすく表示します。そして、exit; という命令でプログラムをその場で強制終了させます。
    - ※通常「警告」などはプログラムが止まりませんが、この関数を使うと小さなミスでも即座にストップさせる厳しいルールになります。
 
  5. それ以外のエラーのとき (return false): 
    - もし「致命的なエラー」など、上の条件に合わないエラーだった場合は false を返します。これはPHPに「あとは任せた（標準のルールで処理して）」と伝える合図です。

### define();
[php.net](https://www.php.net/manual/ja/function.define.php)

PHPで **「定数（ていすう）」を作るための関数**です。

`$name` や `$hp` は「**変数**」といって、中身を自由に入れ替えることができました。 それに対して、define() で作る「**定数**」は、一度決めたら絶対に中身を変えることができません。

- **【書きかたのルール】**
  - 名前は「大文字」で書く: プログラミングの世界では、変数と見分けやすくするために、定数は全部大文字で書くという約束事があります。
  - `$`はつけない: 変数ではないので、頭に`$`は不要です。

- **【使用例】**
  - 消費税: `define("TAX", 1.1);`
  - 最大レベル: `define("MAX_LEVEL", 99);`
  - DBホスト名: `define('DB_USER', 'root');`

### require_once();
[php.net](https://www.php.net/manual/ja/function.require-once.php)

PHPで他のファイルに書かれたプログラムを読み込んで、自分のプログラムの中で使えるようにする命令です。

一言でいうと、 **「そのファイルを1回だけ、絶対に読み込んでね！」** という、とても慎重で厳しい命令です。

似ている `require` と比較します。
- **【特別ルール】**
     ```
     require
     ``` 
     命令するたびに、何度でもそのファイルを読み込みます。
    ```
    require_once
    ``` 
    「もう読み込んだかな？」とPHPがチェックします。もしすでに読み込み済みなら、2回目は何もしません。
- **【特徴】**
  - 面白いことに、require_once は厳密には「関数」ではなく、 **「言語構造（げんごこうぞう）」** というPHPの基本ルールの一部です。そのため、通常の関数のように `require_once("file.php"); `とカッコをつける必要はありません。一般的な記述方法として`require_once 'file.php';`と記述します。

### function connectPdo()
自作メソッド。 

一言でいうと **「データベースと通信するための『専用の窓口』を準備する」** という仕事をしています。

- **【`try`の中身】**
  ```
  return new PDO(DSN, DB_USER, DB_PASSWORD);
  ```
    - `new PDO`：「データベースに接続するためのインスタンス」を新しく作れ！という命令です。
      - ※PDOメソッドは**PHP側で公式にすでに用意されているメソッド**になります。
    - `DSN, DB_USER, DB_PASSWORD`：[上記で話した`define() `](#define)で作られた「定数」たちです。ここにはデータベースの住所や、入るためのIDとパスワードが「書きかえられない大切なルール」として保存されています。
    - `return`：準備ができた「接続窓口」を、この関数を呼び出した人に「はい、どうぞ！」と返しています。

- **【`catch`の中身】（もし失敗したら...）**
  - データベースの住所が間違っていたり、パスワードが違ったりすると、プログラムがエラー（例外）を投げます。それを捕まえるのが **catch（キャッチ）** です。
  - `echo $e->getMessage()`：「どうして失敗したのか（パスワードが違うよ、など）」という理由を画面に表示します。
    - `$e`の中身については定義されていませんが、PHPには `Exception` や `PDOException` という名前の「エラー報告書の設計図」が最初から用意されています。それを`$e`にいれたということになります。[※PDOExceptionについて](https://www.php.net/manual/ja/class.pdoexception.php)
  - `exit()`：データベースに繋がらないとこの後のプログラムは動かせないので、**その場で実行を終了させます。**

### function createTodoData($todoText)
<!-- (sc20) -->
自作メソッド。

**「ユーザーが入力した新しいTodoの内容を、データベースの『todos』テーブルに安全に保存する」** ための処理を行っています。<br>
「プレースホルダ」や「SQLインジェクション対策」がすべて組み込まれた、実戦的なコードです。

- **【引数】**
  - **$todoText**：ブラウザ上で入力された内容。

- **【していること】**

  1. **データベース接続**<br>
    ```
    $dbh = connectPdo();
    ```
    - [connectPdo()](#function-connectpdo)関数を呼び出しています。その関数を`$dbh`という名前の変数（ハンドル）に入れています。
  2. **SQL文のテンプレート作成**<br>
    ```
    $sql = 'INSERT INTO todos (content) VALUES (:todoText)';
    ```
    - `INSERT INTO...`：<br>
    データベースに新しいデータを追加するための命令です。
    - `:todoText`：<br>
    「名前付きプレースホルダ」です。ここでは具体的な値（Todoの内容）を直接書かず、「後でここに入れるよ」という予約席にしています。
  3.  **命令の準備（プリペア）**<br>
    ```
    $stmt = $dbh->prepare($sql);
    ```
    - [`PDO::prepare()`](https://www.php.net/manual/ja/pdo.prepare.php)：<br>
    データベースに対して「今からこの形の命令を送るから、準備しておいてね」と伝える関数です。これにより、**命令の骨組みが先に固定され、後から悪意のあるプログラムが混入するのを防ぎます（SQLインジェクション対策）。**
  4. **値の紐付け（バインド）**<br>
    ```
    $stmt->bindValue(':todoText', $todoText, PDO::PARAM_STR);
    ```
    - [`PDOStatement::bindValue`](https://www.php.net/manual/ja/pdostatement.bindvalue.php)：<br>予約席 `:todoText` に、実際の変数 `$todoText` の中身を座らせる作業です。
    - [`PDO::PARAM_STR`](https://www.php.net/manual/ja/pdo.constants.php#pdo.constants.param-str)：<br>ここに入るデータは「文字列（String）」であることを明示しています。これにより、データベースは中身を「実行すべき命令」ではなく「単なる文字データ」として正しく扱います。
  5. **命令の実行**<br>
  ```
  $stmt->execute();
  ```
  - [`PDOStatement::execute()`](https://www.php.net/manual/ja/pdostatement.execute.php)：<br>
  すべての準備が整ったので、実際にデータベースへ書き込みを実行する合図です。この瞬間、Todoリストに新しい項目が追加されます。

### getAllRecords()
<!-- (sc13) -->
自作メソッド。
- **【引数】**
  - なし

- **【していること】**

  1. データベース接続
    ```
    $dbh = connectPdo();
    ```
    - [connectPdo()](#function-connectpdo) 関数を呼び出しています。その関数を`$dbh `という名前の変数（ハンドル）に入れています。
  2. SQLを作成
    ```
    $sql = 'SELECT * FROM todos WHERE deleted_at IS NULL';
    ```
    - 今回のSQLとして、 `todos`テーブルにある`deleted_at`(削除日時)がNULL(データがない)もの全てを表示させる。という内容になります。
    - getAllRecords()が呼び出された時に実行したいSQLを作成しています。
  3.  命令を実行（query）する
    ```
    return $dbh->query($sql)->fetchAll();
    ```
    - `query($sql)`：`$dbh`を使用してデータベースにアクセスし、`query($sql)`でSQLを実行しています。  
    - `fetchAll()`： 見つかったデータを、1つずつではなく **「全部まとめてリスト（配列）」の形** にします。[※`fetchAll()`について](https://www.php.net/manual/ja/pdostatement.fetchall.php)
    - `return`：出来上がったリストを、この関数を呼び出した人に「はい、これが最新のリストだよ！」と手渡して終了します。

### updateTodoData($post)
<!-- (sc19) -->
自作メソッド
- **【引数】**
  - **$post**：更新したい入力した内容。

- **【していること】**
  1. **データベース接続**<br>
    ```
    $dbh = connectPdo();
    ```
    - [connectPdo()](#function-connectpdo) 関数を呼び出しています。その関数を`$dbh`という名前の変数（ハンドル）に入れています。

  2. **SQL文（更新命令）のテンプレート**<br>
    ```
    $sql = 'UPDATE todos SET content = "' . $post['content'] . '" WHERE id = ' . $post['id'];
    ```
    - `UPDATE todos SET...`：<br>
    「todos」テーブルのデータを更新せよ、という命令です。
    - `WHERE id = :id`：<br>これが非常に重要です。「どのIDのデータを更新するか」を限定しています。これがないと、テーブル内のすべてのTodoが同じ内容に書き換わってしまうため、特定の1件を狙い撃ちするために必須の条件です。
    - `:todoText` と `:id`：<br>名前付きプレースホルダ（予約席）です。
  3.  **命令の準備（プリペア）**<br>
    ```
    $stmt = $dbh->prepare($sql);
    ```
    - [`PDO::prepare()`](https://www.php.net/manual/ja/pdo.prepare.php)：<br>
    データベースにSQLの骨組みを送り、実行の準備をさせます。これにより、後から送るデータが「命令」として誤作動するのを防ぐ **SQLインジェクション対策** が行われます。
  4. **データの紐付け（バインド）**<br>
  ここでは、予約席に実際のデータを座らせる作業を2回行っています。<br>
  ```
  $stmt->bindValue(':todoText', $post['content'], PDO::PARAM_STR);
  $stmt->bindValue(':id', (int) $post['id'], PDO::PARAM_INT);
  ```
  - **`:todoText `へのバインド**：<br>
   ユーザーが編集した新しい本文（`$post['content']`）を「文字列（`PARAM_STR`）」として紐付けます。
  - **`:id` へのバインド**：<br>
    編集対象の番号（`$post['id']`）を「整数（`PARAM_INT`）」として紐付けます。
    - ここで (`int`) と書いているのは、念のためにデータを数値型に変換（キャスト）して、より安全かつ確実に処理するためです。
  5. **命令の実行**<br>
  ```
  $stmt->execute();
  ```
  - [`PDOStatement::execute()`](https://www.php.net/manual/ja/pdostatement.execute.php)：<br>
  準備したテンプレートにデータを流し込み、実際にデータベースの書き換えを実行します。

### function getTodoTextById($id)
<!-- (sc20) -->
自作メソッド

**「指定したID（番号）に対応する『やること（Todo）』の本文だけを、データベースからピンポイントで持ってくる」** ための処理を行っています。
- **【引数】**
  - **$id**：`$_GET['id']` のURLクエリパラメータ（index.phpでURLのパラメータとして渡したid）

- **【していること】**
  1. **データベース接続**<br>
    ```
    $dbh = connectPdo();
    ```
    - [connectPdo()](#function-connectpdo) 関数を呼び出しています。その関数を`$dbh`という名前の変数（ハンドル）に入れています。
  2. **SQL文のテンプレート作成**<br>
    ```
    $sql = 'SELECT * FROM todos WHERE deleted_at IS NULL AND id = :id';
    ```
    - `SELECT * FROM todos`：<br>
    todosテーブルの全項目を取得せよ、という命令です。
    - `WHERE deleted_at IS NULL`：<br>
    これは「ゴミ箱に入っていない（削除されていない）データのみ」という条件です。
    - `AND id = :id`：<br>
    「かつ、IDが指定したものと一致するデータのみ」に絞り込んでいます。これによって、特定の1件だけを狙い撃ちします。
  3.  **安全な準備と紐付け**<br>
    ```
    $stmt = $dbh->prepare($sql);
    $stmt->bindValue(':id', (int) $id, PDO::PARAM_INT);
    ```
    - [`PDO::prepare()`](https://www.php.net/manual/ja/pdo.prepare.php)：<br>
    データベースにSQLの骨組みを送り、実行の準備をさせます。これにより、後から送るデータが「命令」として誤作動するのを防ぐ **SQLインジェクション対策** が行われます。
    - [`bindValue()`](https://www.php.net/manual/ja/pdostatement.bindvalue.php)：<br>
    予約席 `:id `に、実際の数値 `$id` を流し込みます。
    - [`PDO::PARAM_INT`](https://www.php.net/manual/ja/pdo.constants.php#pdo.constants.param-int)：ここに入るのは必ず「整数（Integer）」であると指定することで、より安全性を高めています。
  4. **データの取り出し（フェッチ）**<br>
    ```
    $stmt->execute();
    $data = $stmt->fetch();
    ```
    - [`PDOStatement::execute()`](https://www.php.net/manual/ja/pdostatement.execute.php)：<br>
    準備したテンプレートにデータを流し込み、実際にデータベースの書き換えを実行します。
    - [`PDOStatement::fetch()`](https://www.php.net/manual/ja/pdostatement.fetch.php)：<br>
    データベースから返ってきた結果（1行分のデータ）を、PHPで扱いやすい配列の形（連想配列）に変換して`$data`に格納します。
  5. **結果を呼び出し元に返す**<br>
    ```
    return $data['content'];
    ```
    - `return`：<br>
    プログラムの制御と結果を、この関数を呼び出した場所に返します。
    - ここでは、配列 `$data`の中にある `['content']`（Todoの本文が入っている棚）の中身だけを選んで返しています。

### function deleteTodoData($id)
<!-- (sc20) -->
**「データベースのデータを完全に消去するのではなく、『削除済み』というスタンプを押して、一覧に出ないようにする（論理削除）」** という処理をしています。

- **【引数】**
  - **$id**：削除したい入力したレコードのid

- **【していること】**
  1. **データベース接続**
    ```
    $dbh = connectPdo();
    ```
    - [connectPdo()](#function-connectpdo) 関数を呼び出しています。その関数を`$dbh`という名前の変数（ハンドル）に入れています。
  2. **現在日時の取得と整形**
    ```
    $now = date('Y-m-d H:i:s');
    ```
    - `date()`：ソースによると、この関数は指定した書式で日付や時刻を文字列にするためのものです。
    - ここでは「2026-07-24 18:30:00」のような、「今まさに削除ボタンが押された瞬間」の時刻を作って変数 `$now` に入れています。
  3.  **SQL文のテンプレート作成**<br>
    ```
    $sql = 'UPDATE todos SET deleted_at = :now WHERE id = :id';
    ```
    - `UPDATE todos SET deleted_at = :now: `：<br>
    todos」テーブルの deleted_at カラムに、削除した時刻を書き込む命令です。
    - `WHERE id = :id`：<br>
    どのデータを更新するかを限定しています。特定の1件を狙い撃ちするために必須の条件です。
    - `:now` と `:id:`：<br>
     名前付きプレースホルダ（予約席）です。
  4.  **命令の準備（プリペア）**<br>
    ```
    $stmt = $dbh->prepare($sql);
    ```
    - [`PDO::prepare()`](https://www.php.net/manual/ja/pdo.prepare.php)：<br>
    データベースにSQLの骨組みを送り、実行の準備をさせます。これにより、後から送るデータが「命令」として誤作動するのを防ぐ **SQLインジェクション対策** が行われます。

  5. **データの紐付け（バインド）**
    ```
    $stmt->bindValue(':now', $now, PDO::PARAM_STR); 
    $stmt->bindValue(':id', (int) $id, PDO::PARAM_INT);
    ```
    - **`:now `へのバインド**：<br>
    生成した現在日時（`$now`）を「文字列（`PARAM_STR`）」として紐付けます。
    - **`:id `へのバインド**：<br>
    削除対象の番号（`$id`）を「整数（`PARAM_INT`）」として紐付けます。 ここで (`int`) と書いているのは、念のためにデータを整数型に変換（キャスト）して、より安全かつ確実に処理するためです。
  6. **命令の実行**<br>
  ```
  $stmt->execute();
  ```
  - [`PDOStatement::execute()`](https://www.php.net/manual/ja/pdostatement.execute.php)：<br>
  準備したテンプレートにデータを流し込み、実際にデータベースの書き換え（削除日時の記録）を実行します。

### function getRefererPath()
自作メソッド。

**「ユーザーが直前に開いていたページのURLから、『パス（住所の後半部分）』だけを抜き出して特定する」** という仕事をしています。

- **【引数】**
  - なし

- **【していること】**
 1. 直前のページの情報を取得する
  - `$_SERVER['HTTP_REFERER']` ：ブラウザがサーバーに送ってくる情報の一つで、**「ユーザーがどのページからリンクを辿って現在のページに来たか」** という直前のURLが入っています。[※$_SERVERについて](https://www.php.net/manual/ja/reserved.variables.server.php)
2. URLをバラバラに分解する（parse_url）
  - `$urlArray = parse_url($_SERVER['HTTP_REFERER']);`
    - [`parse_url()`](https://www.php.net/manual/ja/function.parse-url.php): この関数は、**URLを解釈して、その構成要素（プロトコル、ホスト名、パスなど）をバラバラに分解して返す**役割を持っています。
    - 実行結果：例えば直前のURLが `https://example.com/index.php` だった場合、この関数によって「ホスト名は `example.com`」「パスは /index.php」といった具合に整理されたリスト（配列）が作成され、変数 `$urlArray` に保存されます。
3. パスだけを抜き出して返す（return）
  - `return $urlArray['path'];`
    - `$urlArray['path']`：分解されたリストの中から、「path（パス）」 というラベルが付いた情報（例：`/index.php`）だけを取り出しています。
    - `return`：**プログラムの制御を呼び出し元に戻し**、取り出したパスの文字列を関数の結果として「はい、どうぞ！」と返します。

### function savePostedData($post) 
自作メソッド

**「送られてきたデータの内容と、そのデータが『どの画面から送られてきたか』をチェックして、実行する作業（保存・更新・削除）を自動で振り分ける司令塔」** の役割をしています。

- **【引数】**
  - **$post**：どこから来たかを確認する。

- **【していること】**
  1. 「どこから来たか」を特定する
    - `$path = getRefererPath();`
    - [getRefererPath()](#function-getrefererpath) 関数を呼び出しています。これにより、ユーザーが「新規作成画面 (/`new.php`)」「編集画面 (`/edit.php`)」「一覧画面 (`/index.php`)」のどこからボタンを押してここに来たのか、そのパスを特定して変数 `$path` に入れています。
  2. switch 文による処理の振り分け
    - 取得した `$path` の値に応じて処理を分岐させています。`switch` 文は、同じ式（ここでは `$path`）を異なる値と比較し、一致した場所のコードを実行するために使われます。
      - `case '/new.php'` (新規登録)：ユーザーが新規作成画面から来た場合、[`createTodoData()`](#function-createtododatatodotext) 関数を呼び出してデータベースに新しい Todo を登録（INSERT）します。
      - `case '/edit.php'` (更新)：編集画面から来た場合、[`updateTodoData()`](#updatetododatapost) 関数を呼び出して既存のデータを書き換え（UPDATE）ます。
      - `case '/index.php' `(削除)：一覧画面の削除ボタンから来た場合、[`deleteTodoData()`](#function-deletetododataid) 関数を呼び出して指定された ID のデータを削除します。
  3. break の役割
    - 各 `case` の最後にある `break` は、現在実行中の `switch` 構造を終了させる命令です。もし `break` を書き忘れると、PHP は一致した処理が終わった後も、その下にある別の `case` の命令を続けて実行してしまいます（これをフォールスルーといいます）。そのため、目的の処理だけを行わせるために `break` で「ここで終わり！」と明確に伝えています。
  4. default の役割
    - `default` は、どの `case` にも当てはまらなかった場合に実行される特別なケースです。このコードでは何もせず終了するように書かれています。

### function e($text)
<!-- sc 18 -->
自作メソッド。

Webサイトのセキュリティを守るための **「エスケープ処理（無害化）」を簡単に行うためのショートカット関数** です。

**「画面に文字を出すときに、悪いプログラムが動かないように記号を安全な文字に置き換える『安全装置』を、いつでも簡単に使えるようにしたもの」** だと言えます！

- **【引数】**
  - **$text**：変換したい元の文字です。

- **【していること】**
この関数は、引数で渡された文字列（`$text`）の中に含まれる、HTMLとして特別な意味を持つ記号を **「HTMLエンティティ」という安全な形式に変換** して返します。<br>
具体的に、内部で使われている `htmlspecialchars()` の設定は以下の通りです。
  1. `$text`: 変換したい元の文字です。
  2. `ENT_QUOTES`: 二重引用符（`"`）だけでなく、一重引用符（`'`）も変換対象にするという指示です（※一般的なPHPの仕様に基づきます）。
  3. `'UTF-8'`: 文字コードを UTF-8 として処理することを指定しています。
- **なぜわざわざ e() という関数を作るのか**
プログラムの中で何度も `htmlspecialchars($text, ENT_QUOTES, 'UTF-8') `と書くのは大変ですし、書き間違い（タイポ）の原因にもなります。
  - 記述を短くする：echo e($val); と書くだけで済むため、コードがスッキリします。
  - 設定を統一する：全箇所で同じ ENT_QUOTES や UTF-8 という設定を強制できるため、セキュリティの漏れを防げます。

- セキュリティ上の重要性（以前の会話より）
この処理は**「クロスサイトスクリプティング（XSS）」を防ぐために必須**です。 例えば、ユーザーが入力した `<script>...</script> `という悪意のある文字列をそのまま画面に出すとブラウザで実行されてしまいますが、この関数を通すことで `&lt;script&gt;...` と変換され、単なる「文字」として安全に表示されるようになります。

**「特殊文字を HTML エンティティに変換する」** ための関数です。

**【付属して覚えるべき関数】**

### function setToken()
<!-- sc19 -->
**「なりすまし攻撃（CSRF対策）に使うための、推測不可能な『秘密の合言葉（トークン）』を生成して保存する」** ための処理をしています。

- **【していること】**
  1. `openssl_random_pseudo_bytes(16)`<br>
    まず、この部分で**「非常に強力なランダムな値」**を作っています。
    ソース（関数索引）によると、この関数は**「疑似ランダムなバイト文字列を生成する」**役割を持っています。
  2. `bin2hex(...)`<br>
    次に、ステップ1で作った「バイナリ（生データ）」を、プログラムで扱いやすい **「16進数の文字列」** に変換しています。
    - `bin2hex()` は **「バイナリのデータを16進表現に変換する」** 関数です。
    - これにより、コンピュータにしか読めないデータが `a1b2c3d4...` のような英数字の並びになり、セッションへの保存やHTMLへの埋め込みがしやすくなります。
  3. `$_SESSION['token'] = ...`<br>
  最後に、出来上がった合言葉をセッションという「サーバー側の一時預かり所」に保存します。
  これまでの会話で触れた通り、`$_SESSION` はページを移動してもデータを保持し続けてくれる特別な変数です。
  ここで `['token']` という名前の棚に保存しておくことで、後からユーザーが送信してきた値と照合し、「本当にこのサイトから送られた正しい操作か？」をチェックできるようになります。

### function checkToken($token)
<!-- sc19 -->
`setToken()` で生成した「秘密の合言葉」が、正しく送られてきているかを判定しています。

- **【していること】**
  1. **if 文の条件式（2つの不正チェック）**<br>
  この関数の中核は、if 構文による判定です。ここでは `||` (**論理演算子 OR**) を使い、以下のいずれかの「怪しい状態」に当てはまらないかを確認しています。

  - `empty($_SESSION['token'])`：<br>
  `empty()` 関数は、変数が空であるか、そもそも存在しないかを調べます。ここでは「サーバー側の記録（セッション）に、照合すべき合言葉がそもそも残っていない」という異常事態をチェックしています。

  - `$_SESSION['token'] !== $token`：<br>
  `!==` (**不一致演算子**) を使い、サーバーが覚えている正解（`$_SESSION['token']`）と、ユーザーが画面から送ってきた申告内容（`$token`）が **「値も型も一致しない」** ことを確認しています。

  2. **チェックに引っかかった時の処理**<br>
    条件式のいずれかが `true`（真）になった場合、**つまり不正な操作だと判断された場合**、以下の2つを実行します。
    - `$_SESSION['err'] = '不正な操作です';`：<br> `$_SESSION`（セッション変数）は、サーバー側にユーザーごとのデータを一時保存する場所です
    。ここにエラーメッセージを書き込み、後で画面に表示できるように準備します。<br>
    - `redirectToPostedPage();`: <br>
    不正な操作をそのまま進めず、安全のためにユーザーを元のページ（または指定のページ）へ強制的に追い返します。

- **【この関数の重要性】**<br>
プログラムにとっての **「本人確認の窓口」** のようなものです。

1. **正規のユーザー：**<br>
`setToken()` で作られた正しい合言葉を持っているので、このチェックを無事に通過し、データの保存などの処理に進めます。
2. **攻撃者：**<br>
サーバーの中に隠された正しい合言葉を知りません。適当な値を送ったり、合言葉なしでアクセスしたりしても、この `checkToken()` が「不正な操作です」とブロックして、大切なデータを守ってくれるのです。

**まとめ**：<br>
`checkToken()` は、**「サーバーが隠し持っている正解と、送られてきた値がピッタリ合うか」を厳密に照合し、攻撃者のなりすましを門前払いするセキュリティの要**となる関数です。

### function unsetError()
<!-- sc19 -->
**「セッションに保存されているエラーメッセージを消去（リセット）する」** ための処理を行っています。

- **【していること】**
1. **処理の内容**<br>
`$_SESSION['err'] = '';`<br>
- `$_SESSION`：<br>
PHPのセッション機能（サーバー側でユーザーのデータを保持する仕組み）で使用される特別な変数です。
- `['err']`：<br>
セッションという「データ保管庫」の中にある、エラーメッセージ用の棚（キー）を指定しています。
- `= ''`：その棚の中身を **空文字（中身がない状態）** で上書きします。

2. **この関数の目的**<br>
Webアプリ（今回のTodoアプリなど）では、バリデーションに失敗した際に `$_SESSION['err'] = '入力がありません';` といった形でエラーを記録します。しかし、**一度表示したエラーは、次のページ移動や正しい操作をした後には消えていなければなりません。**
この `unsetError()` を適切なタイミングで実行することで、画面に古いエラーメッセージが「居座る」のを防ぎ、アプリの状態を真っさらに戻す役割を果たしています。

3. **プログラミング上の注意点**<br>
関数名に「unset」という言葉が入っていますが、PHPには `unset()` という「変数の割り当てそのものを解除する（棚ごと削除する）」関数も存在します。

- ユーザーのコード：<br> 
`$_SESSION['err'] = '';` （棚の中身を空にする）
- 別の書き方：<br> 
`unset($_SESSION['err']); `（棚そのものを消す）

今回のコードは「空文字を代入する」という方法で、**「エラーがない状態」** を作り出しているんですよ。

### function validate($post)
<!-- (sc21) -->
**「ユーザーから送信された内容が空でないかをチェックし、もし空であればエラーメッセージをセットして元のページへ押し戻す（バリデーション）」** ための処理を行っています。
- **【引数】**
  - **$post**：入力されたcontentの文字列

- **【していること】**
1. **入力データの存在確認**
```
isset($post['content'])
```
- [`isset()`](https://www.php.net/manual/ja/function.isset.php)：
**「そもそも『content』という名前のデータが届いているか」** を確認しています。<br>
送信されたデータ（`$post`）の中に「content」という項目（Todoの本文）が正しく存在しているか、そしてそれが `null` ではないかを検査します。
2. **空文字の厳密な判定**
```
$post['content'] === ''
```
- `===`：<br>
演算子を使い、入力内容が「空文字（何も書かれていない状態）」であるかを調べます。値が一致し、かつ型も同じであるかを確認する厳密な比較が行われます。
3. **セッションへのエラー記録**
```
$_SESSION['err'] = '入力がありません'; 
```
- 「項目が存在し、かつ中身が空である」という条件が満たされた場合、セッション変数である `$_SESSION `を使って、サーバー側に一時的にエラーメッセージを保存します。これにより、ページを移動した後でも画面に警告を表示できるようになります。
4. **強制的なページ戻しと処理の終了**
```
redirectToPostedPage();
```
自作関数を呼び出し、ユーザーを直前にいた入力画面へ強制的に戻します。この関数の内部では `exit()` 命令などが実行されるため、不備がある場合はこれ以降の保存処理などは一切実行されずにプログラムが終了します。

まとめ：この関数は、**「正しいデータが入力されているかを見張り、不備があればそれを通さず、ユーザーに書き直しを促すための門番」** のような役割を担っています。


### Tips
  また、DBのcontentカラムはNULLを許可しているので本来下記の記述方法が望ましいです。
  ```
  // 「セットされていない」または「空文字」の場合にエラーにする
  if (!isset($post['content']) || $post['content'] === '') {
      $_SESSION['err'] = '入力がありません';
      redirectToPostedPage();
  }
  ```

## store.php
### header();
[php.net](https://www.php.net/manual/ja/function.header.php)

**サーバーからブラウザへ「画面を表示する前の指示（HTTPヘッダ）」を送る**ための関数です。

具体的には、HTMLの中で特別な意味を持つ記号（例えば `<` や `& `など）を、ブラウザがプログラムの命令（タグ）として解釈せず、単なる「文字」として正しく画面に表示できるように `&lt; `や `&amp;` といった形式（HTMLエンティティ）に置き換える役割を担います。

- **【できること】**
  1. 別のページに飛ばす（リダイレクト）
  - 指定したURLへ自動的に画面を切り替えます。処理を終了させる exit; とセットで書くのが鉄則です。 
    ```
    <?php

    header('Location: ./index.php');
    ```
  2. ファイルをダウンロードさせる
  - ブラウザで画面を表示せず、PDFやCSVファイルとしてダウンロードさせたい場合に使います。
    ```
    <?php
    // ダウンロードするファイルの種類（例：PDFファイル）を指定
    header('Content-Type: application/pdf');

    // ダウンロード時のファイル名を「sample.pdf」に指定
    header('Content-Disposition: attachment; filename="sample.pdf"');
    ```
- **【絶対に守るべきルール】**
  - header() は、HTMLや文字（スペースや空行含む）をブラウザに出力する前に実行しなければなりません。
  - ❌ エラーになるNG例
    ```
    <p>こんにちは</p> <!-- 先にHTMLが出力されている -->
    <?php
    header('Location: https://example.com'); // ここでエラー（Cannot modify header information）
    ?>
    ```
  - ⭕ 正しい例
    ```
    <?php
    header('Location: https://example.com'); // 最初に実行する
    exit;
    ?>
    <p>こんにちは</p>
    ```

# 物理削除・論理削除　論争

## 物理削除(Physical Deletion)
### 概要
SQLの `DELETE` 命令などを使用して、データベースから**データそのものを完全に消去する**手法です。<br>
PHPの標準的な関数やメソッド（例：[`unlink()`](https://www.php.net/manual/ja/function.unlink.php) によるファイル削除、[`Table::delete()`](https://www.php.net/manual/ja/mysql-xdevapi-table.delete.php)、`mysqli` での削除など）は、通常この物理削除を指します。
### メリット
1. **ストレージの節約：**<br>
不要なデータが消えるため、データベースの容量を圧迫しません（ソース外の補足情報）。
2. **クエリがシンプル：**<br>
「削除されていないものだけ選ぶ」という条件を付ける必要がなく、単純な SELECT 文で済みます（ソース外の補足情報）。
3. **個人情報保護：**<br>
ユーザーから「データを消してほしい」と要求された際（忘れられる権利）、物理的に消去することで完全な対応が可能です（ソース外の補足情報）。
### デメリット
1. **復旧が不可能：**<br>
以前の会話で確認した通り、一度消すと二度と元に戻せません。
2. **関連データの不整合：**<br>
他のデータがそのデータを参照していた場合、エラーが起きたり、データの繋がりが壊れたりするリスクがあります（ソース外の補足情報）。

## 論理削除(Logical Deletion)
### 概要
[`deleteTodoData`]((#function-deletetododataid)) 関数の例のように、`UPDATE`命令を使って「削除フラグ」や「削除日時」を書き込み、**データは残したまま「消えたこと」にする**手法です。
### メリット
1. **データの復旧が可能：**<br>
「間違えて消した」場合でもフラグを元に戻すだけで**簡単にデータを復旧できます。**
2. **履歴の保持：**<br>
**過去にどのようなデータがあったかという履歴や証跡を管理できる**ため、分析や監査に役立ちます。 

### デメリット
1. **ストレージの増大：**<br>
削除したはずのデータも蓄積され続けるため、長期間運用するとデータベースが肥大化します。
2. **クエリの複雑化：**<br>
データを取得する際、常に `WHERE deleted_at IS NULL` といった「削除されていないデータだけ」を選ぶ条件を書く必要があり、ミスをすると削除済みのデータが画面に出てしまいます。
3. **インデックスへの影響：**<br>
データ量が増えることで、検索速度などのパフォーマンスに影響を与える可能性があります。
